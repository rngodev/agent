# Log

The **log** is the centralized state of an eval - each component interacts with it:

- the [proxy](/docs/concepts#proxy) writes inputs, outputs and errors to it
- the [simulation](/docs/concepts#simulation) reads from it to generate referential inputs and writes to it to manage stateful effects.
- the [audit](/docs/concepts#audit) reads from it to surface signals, and then writes back to it to record them

It is implemented as [SQLite](https://sqlite.org). The [`rngo eval`](/docs/cli/eval) CLI command will put the log's DB file in the [eval's directory](/docs/cli/eval#capturing-outputs).

## Schema

The database schema is a public interface that is primarily used by [signals](/docs/spec/signal), which are configured using direct SQL queries against the log.

Additionally, external scripts may query the log to aid in additional evaluation or signal discovery.

```sql
CREATE TABLE inputs (
    id INTEGER NOT NULL,
    effect TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    data TEXT NOT NULL,
    metadata TEXT NOT NULL
);

CREATE TABLE outputs (
    channel TEXT NOT NULL,
    input_id INTEGER,
    timestamp INTEGER NOT NULL,
    level TEXT NOT NULL,
    data TEXT NOT NULL,
    metadata TEXT NOT NULL
);

CREATE TABLE metadata (
    type TEXT NOT NULL,
    segment TEXT,
    timestamp INTEGER,
    input_id INTEGER,
    output_id INTEGER,
    data TEXT
);
```

- `inputs` has one row per input generated by an [effect](/docs/spec/effect)
- `outputs` has one row per output received by a [channel](/docs/spec/channel). An interactive output references the input that caused it with `input_id`; otherwise it is null.
- `metadata` records additional information about the simulation, told apart by `type`, such as its start / end times (`timing`), skipped attempts (`skipped`) and signal results (`signal`). Types starting with `_` are internal and may change in any release.

Timestamps are milliseconds since the Unix epoch. An input's is its logical time; an output's is when it was reported. The `data` column of `inputs` and `metadata`, and the `metadata` columns, hold JSON. An output's `data` is plain text.

## Version

This is version 1 of the log schema. Each log records its version in SQLite's `PRAGMA user_version`. See [LOG.md](https://github.com/rngodev/rngo/blob/main/LOG.md) for every column and metadata type, and [MIGRATING.md](https://github.com/rngodev/rngo/blob/main/MIGRATING.md) for changes between versions.
